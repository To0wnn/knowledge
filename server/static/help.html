Connect a client

How to connect Claude Code, agy (Antigravity) or Codex to the shared knowledge: the docs and memory of your project, live on every machine, with the same house rules.

Receive the token safely. Ask for a one-time Bitwarden Send link, not a chat or e-mail message. Never put the token in a memo, doc or git repository.

Claude Code

The most complete connection: the plugin loads the context and house rules at every start, writes a session log and mirrors your docs.

  1. Get the knowledge scripts Needs git and python3. 
    git -C ~/knowledge pull 2>/dev/null || git clone https://github.com/To0wnn/knowledge ~/knowledge
  2. Run the setup It asks for the token you received (paste it; it is not shown), checks it with the server and keeps it in the keyring (Linux) or the Keychain (macOS); with a token already stored it asks whether to replace it. Then it installs the plugin and turns Claude's local auto memory off (your memory is on the server). A server or container without a desktop has no keyring: the setup then says how to set the token instead. Run it again later to update. 
    python3 ~/knowledge/clients/knowledge-agent.py install claude
  3. Only for a guest project: mark your project folder In the root of your project, a file .knowledge-project with the project name you got (for example a350); from then on its .md files go to the server. Code, .venv and hidden folders never go. 
    echo a350 > .knowledge-project
  4. Check Start a new session in your project folder. It begins with knowledge (project …). Ask: "search the knowledge for …".

Which project does my session get?

At every start the server picks the project whose memory and context the session gets:

  1. A token for one project (a guest): always that project, whatever the folder is called, also on Windows.
  2. Otherwise the folder you start the agent in:
Folder (example)Project
a name starting with trade anywhere in the pathtrade
~/<project name>/…, e.g. ~/gemathat project
anpitek anywhere in the pathanpitek
anything else, e.g. ~/Workhomelab

A folder name counts only when it is exactly the name of a project (admin page, Projects): ~/a350 works, ~/A350Copilot does not. A new project of your own: create it under Projects, then start the agent in a folder with that name.

.knowledge-project does something else: it marks a folder whose .md files are mirrored to the server as the docs of that project. It only works with a token for one project, and the name in the file must be that project. Your own devices do not need it.

When it does not work

What you seeCause and fix
401 or "token invalid"Token copied wrongly or revoked. Set it again; ask for a new one if needed.
No context at start (Windows)Git for Windows or Python missing, or the token not in the Credential Manager (cmdkey /list:knowledge shows it). Install both or store the token, then start again.
Setup says "No token"It ran without a terminal (it can only ask in one): run it in a terminal, or set KNOWLEDGE_TOKEN.
A new token, or the old one revokedRun the setup again and answer y when it asks whether to replace the stored token.
The session gets the wrong projectThe folder name does not match a project exactly, or the token is for one project only: see "Which project does my session get?".
Docs do not reach the serverNo .knowledge-project in the project root, or its name does not match your token's project.
Codex ignores the context hookMore than one SessionStart hook, or the hook is not trusted yet: open /hooks in Codex.
"writes are allowed only for …"Your token may not write that path: only the memory of your own project.
"knowledge server unreachable: offline mode"The server is down. The agent works in your offline copy (~/.knowledge/mirror/); what it writes goes up at the next start. A memo changed on both sides is kept as <name>.offline-<time>.md to merge.
