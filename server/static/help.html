Connect a client

How to connect Claude Code, agy (Antigravity) or Codex to the shared knowledge: the docs and memory of your project, live on every machine, with the same house rules.

One token per deviceYou get it from the admin of this server. It decides which project you see and whether you may write.
Memory lives on the serverMemos are central; every session, on every machine, reads and writes the same files.
Your folder stays the sourceCode stays with you. Only your .md files are mirrored (Claude Code).
Receive the token safely. Ask for a one-time Bitwarden Send link, not a chat or e-mail message. Never put the token in a memo, doc or git repository.

Claude Code

The most complete connection: the plugin loads the context and house rules at every start, writes a session log and mirrors your docs.

  1. Windows: Git and Python Install Git for Windows (Claude Code runs hooks in Git Bash) and Python 3 with the py launcher. Linux and macOS usually have Python already.
  2. Install the plugin 
    claude plugin marketplace add To0wnn/knowledge
claude plugin install knowledge@knowledge --scope user
  3. Set the URL and token 
    claude plugin configure knowledge@knowledge
    URL: https://knowledge.to0wnn.com, token: the one you received.
  4. Turn local auto memory off In ~/.claude/settings.json (Windows: %USERPROFILE%\.claude\settings.json): 
    "autoMemoryEnabled": false
    Your memory is on the server, so Claude does not also write it locally.
  5. Mark your project folder (only when your folder is the source) In the root of your project, a file .knowledge-project with the project name (for example a350): 
    echo a350 > .knowledge-project
    From then on every .md file goes to the server at each start, and each changed one right after the change. Code, .venv and hidden folders never go.
  6. Check Start a new session in your project folder. It begins with knowledge (project …). Ask: "search the knowledge for …".

agy (Antigravity CLI)

agy is a standalone binary that updates itself (agy update), not an npm package. It gets the tools and, through a rules file, the house rules.

  1. Add the MCP server 
    agy mcp add --header "Authorization: Bearer YOUR_TOKEN" knowledge https://knowledge.to0wnn.com/mcp
    This lands in ~/.gemini/config/mcp_config.json (fields serverUrl and headers).
  2. Protect the config file agy keeps the token in plain text in that file. 
    chmod 600 ~/.gemini/config/mcp_config.json
    Windows: make the file readable for your own account only (Properties › Security).
  3. House rules as a rules file Save the house rules (the list below, also claude/house_rules.md on the server) as ~/.gemini/GEMINI.md; agy always loads that file. With the hooks (next step) the rules also arrive with the context at every start, so this file is the fallback.
  4. Hooks: context, session log, mirror 
    git clone https://github.com/To0wnn/knowledge ~/knowledge
python3 ~/knowledge/clients/knowledge-agent.py install agy
    Windows: py instead of python3 and %USERPROFILE%\knowledge instead of ~/knowledge. This writes ~/.gemini/config/hooks.json (an existing one is kept as .bak). The hooks take the token from KNOWLEDGE_TOKEN (see above for Codex; for agy set it the same way); session log and mirror need a write token. agy has no session-end event, so the log gets one entry per turn.
  5. Check 
    agy mcp list
    knowledge http enabled. In a session, /mcp shows the connection.

Codex (OpenAI)

Codex reads the token from an environment variable, so it is not stored in a config file. Install or update with npm i -g @openai/codex@latest.

  1. Token as an environment variable 
    # Linux/macOS (in ~/.bashrc or ~/.zshrc)
export KNOWLEDGE_TOKEN="YOUR_TOKEN"

# Windows (PowerShell, once; then open a new window)
setx KNOWLEDGE_TOKEN "YOUR_TOKEN"
  2. The MCP server in ~/.codex/config.toml 
    [mcp_servers.knowledge]
url = "https://knowledge.to0wnn.com/mcp"
bearer_token_env_var = "KNOWLEDGE_TOKEN"
default_tools_approval_mode = "writes"
startup_timeout_sec = 15
    writes: reading just works, Codex asks before writing.
  3. House rules in ~/.codex/AGENTS.md The house rules (the list below) as ~/.codex/AGENTS.md. Codex loads this file at every start; with the hooks the rules also arrive with the context.
  4. Hooks: context, session log, mirror 
    git clone https://github.com/To0wnn/knowledge ~/knowledge
python3 ~/knowledge/clients/knowledge-agent.py install codex
    Windows: py instead of python3 and %USERPROFILE%\knowledge instead of ~/knowledge. This writes ~/.codex/hooks.json (an existing one is kept as .bak). The hooks take the token from KNOWLEDGE_TOKEN (see above for Codex; for agy set it the same way); session log and mirror need a write token. Trust the hooks once with /hooks in a session: Codex skips new or changed hooks until then.
  5. Check 
    codex mcp list
    Ask in a session: "search the knowledge for …".
Hooks in Codex. Keep exactly one SessionStart hook: with several, Codex drops the context. Codex runs hooks with a bare PATH, so use full paths.

The house rules

When it does not work

What you seeCause and fix
401 or "token invalid"Token copied wrongly or revoked. Set it again; ask for a new one if needed.
No context at start (Claude Code, Windows)Git for Windows missing or Python not found. Install both and restart Claude Code.
Docs do not reach the serverNo .knowledge-project in the project root, or its name does not match your token's project.
Codex ignores the context hookMore than one SessionStart hook, or the hook is not trusted yet: open /hooks in Codex.
"writes are allowed only for …"Your token may not write that path: only the memory of your own project.
