Connect a client

How to connect Claude Code, agy (Antigravity) or Codex to the shared knowledge: the docs and memory of your project, live on every machine, with the same house rules.

Receive the token safely. Ask for a one-time Bitwarden Send link, not a chat or e-mail message. Never put the token in a memo, doc or git repository.

Claude Code

The most complete connection: the plugin loads the context and house rules at every start, writes a session log and mirrors your docs.

  1. Put the token in the keyring Paste the token you received at the Password: prompt (it is not shown). Every agent on this computer reads it from there; it is in no file. 
    secret-tool store --label="Knowledge server token" service knowledge
    No secret-tool? Install libsecret (Arch) or libsecret-tools (Debian/Ubuntu). A server or container without a desktop has no keyring: there give the token to the plugin instead (URL https://knowledge.to0wnn.com, then the token); it is kept in ~/.claude/.credentials.json, readable only by you. 
    claude plugin configure knowledge@knowledge
  2. Install the plugin 
    claude plugin marketplace add To0wnn/knowledge
claude plugin install knowledge@knowledge --scope user
    It may say that options are not set yet: that is fine, the plugin takes the token from the keyring (step 1).
  3. Turn local auto memory off Add this line to ~/.claude/settings.json; your memory is on the server, so Claude does not also write it locally: 
    "autoMemoryEnabled": false
  4. Only for a guest project: mark your project folder In the root of your project, a file .knowledge-project with the project name you got (for example a350): 
    echo a350 > .knowledge-project
    From then on every .md file goes to the server at each start, and each changed one right after the change. Code, .venv and hidden folders never go.
  5. Check Start a new session in your project folder. It begins with knowledge (project …). Ask: "search the knowledge for …".

agy (Antigravity CLI)

The knowledge plugin connects agy: the tools, the context at every start (with the house rules), the session log, the docs mirror and the shared development skills. On Windows a setup script does it for now. agy itself comes from antigravity.google and updates itself (agy update).

  1. Put the token in the keyring Paste the token you received at the Password: prompt (it is not shown). Every agent on this computer reads it from there; it is in no file. 
    secret-tool store --label="Knowledge server token" service knowledge
    No secret-tool? Install libsecret (Arch) or libsecret-tools (Debian/Ubuntu). A server or container without a desktop has no keyring: there put the token in your profile instead, then log in again. 
    echo 'export KNOWLEDGE_TOKEN="YOUR_TOKEN"' >> ~/.profile
  2. Install the plugin 
    agy plugin install https://github.com/To0wnn/knowledge/tree/main/plugin
    The plugin's MCP server reads the token from the keyring each time, so it is in no file. Set up with the old setup script before? Then remove its knowledge entries from ~/.gemini/config/mcp_config.json and ~/.gemini/config/hooks.json first, or agy loads the server and the hooks twice.
  3. Only for a guest project: mark your project folder In the root of your project, a file .knowledge-project with the project name you got (for example a350): 
    echo a350 > .knowledge-project
    From then on every .md file goes to the server at each start, and each changed one right after the change. Code, .venv and hidden folders never go.
  4. Check 
    agy plugin list
    It lists knowledge as enabled. Start agy and ask: "search the knowledge for …".
  5. Later: update Run the install command again.
  1. Install Git and Python Git for Windows and Python 3 (keep "py launcher" ticked). The steps below are for PowerShell.
  2. Put the token in an environment variable The setup and the hooks read it from there; it never goes into a file you share. 
    setx KNOWLEDGE_TOKEN "YOUR_TOKEN"
    Then close this window and open a new PowerShell.

It is safe to run again; an existing file is extended, not replaced.

    From then on every .md file goes to the server at each start, and each changed one right after the change. Code, .venv and hidden folders never go.
  5. Check 
    agy mcp list
    It lists knowledge http enabled. Start agy and ask: "search the knowledge for …".

    git -C $HOME\knowledge pull

Which project does my session get?

At every start the server picks the project whose memory and context the session gets:

  1. A token for one project (a guest): always that project, whatever the folder is called, also on Windows.
  2. Otherwise the folder you start the agent in:
Folder (example)Project
a name starting with trade anywhere in the pathtrade
~/<project name>/…, e.g. ~/gemathat project
anpitek anywhere in the pathanpitek
anything else, e.g. ~/Workhomelab

A folder name counts only when it is exactly the name of a project (admin page, Projects): ~/a350 works, ~/A350Copilot does not. A new project of your own: create it under Projects, then start the agent in a folder with that name.

.knowledge-project does something else: it marks a folder whose .md files are mirrored to the server as the docs of that project. It only works with a token for one project, and the name in the file must be that project. Your own devices do not need it.

When it does not work

What you seeCause and fix
401 or "token invalid"Token copied wrongly or revoked. Set it again; ask for a new one if needed.
No context at start (Windows)Git for Windows or Python missing, or a PowerShell window opened before setx. Install both, open a new window, start again.
Setup says "No token"Linux: the token is not in the keyring yet (step 1; secret-tool lookup service knowledge shows it). Windows: KNOWLEDGE_TOKEN is not set in this window: step 1, then a new PowerShell.
The session gets the wrong projectThe folder name does not match a project exactly, or the token is for one project only: see "Which project does my session get?".
Docs do not reach the serverNo .knowledge-project in the project root, or its name does not match your token's project.
Codex ignores the context hookMore than one SessionStart hook, or the hook is not trusted yet: open /hooks in Codex.
"writes are allowed only for …"Your token may not write that path: only the memory of your own project.
"knowledge server unreachable: offline mode"The server is down. The agent works in your offline copy (~/.knowledge/mirror/); what it writes goes up at the next start. A memo changed on both sides is kept as <name>.offline-<time>.md to merge.
