Connect a client

How to connect Claude Code, agy (Antigravity) or Codex to the shared knowledge: the docs and memory of your project, live on every machine, with the same house rules.

Receive the token safely. Ask for a one-time Bitwarden Send link, not a chat or e-mail message. Never put the token in a memo, doc or git repository.
Your computer:

Install

  1. Get the scripts and run the setup Needs git and python3. Needs Git for Windows and Python 3 (keep "py launcher" ticked), in PowerShell. Quit Codex and agy first. It finds your agents (y/n for each), asks for the server address (this page's address) and your token, installs the plugin, and offers to import what your agents already know. 
    curl -fsSL https://raw.githubusercontent.com/To0wnn/knowledge/main/install.sh | sh
    irm https://raw.githubusercontent.com/To0wnn/knowledge/main/install.ps1 | iex
  2. The companion An optional helper at logon (127.0.0.1:47321) for chats, workers and approvals from the web UI. The setup asks; --plugin-only skips it, knowledge-agent.py install-companion adds it later. The token's "agents" switch on the admin page decides whether this pc may be steered at all.
  3. Link your project folder A file .knowledge-project with the project name in the project's root: sessions there get that project, and its .md files become the project's docs. Link it on the companion page (Folders), in the web UI under Machines, by asking your agent, or by hand: 
    echo garden > .knowledge-project
    Set-Content .knowledge-project garden
  4. First start Start a new session in your project folder; each agent has one thing to do the first time, see its tab below. Then ask: "search the knowledge for …".

Update

The plugin updates itself (a new version loads at the next start). To add an agent you installed later, run the same setup line again.

Claude Code

The plugin loads the context and house rules at every start, writes a session log and mirrors your docs. The setup turns Claude's local auto memory off: your memory is on the server.

First start: a new session begins with knowledge (project …). Nothing else to do.

agy (Antigravity CLI)

The plugin gives agy the tools, the context at every start (with the house rules), the session log, the docs mirror and the shared development skills. agy itself comes from antigravity.google and updates itself (agy update).

First start: after your first prompt agy asks to run a small agent_hooks.py register command, so other agents on this computer can hand it tasks. Allow it ("always allow" saves asking again).

Windows: agy needs the python3 command, which Python from the python.org install manager or the Microsoft Store has. With only py the setup says so and sets agy up without the plugin.

Codex (OpenAI)

The plugin gives Codex the tools, the context at every start (with the house rules), the session log, the docs mirror and the shared development skills. Install or update Codex with npm i -g @openai/codex@latest.

First start: the companion trusts the knowledge hooks for you, again after each plugin update. Without the companion, type /hooks once and trust them; Codex skips new hooks until then, and asks again after an update with new hooks.

Agents hand each other tasks

When one agent writes a task line for another (open until <date> [Codex, ID] from Claude, start now: …), a pc whose companion runs that agent's workers for the project starts a fresh worker session for it; with no such pc, that agent's next chat in the project starts it. The result comes back as a line [Claude, ID-done]: …. The Tasks tab shows per task where it runs or why it waits.

Agents and chats in the web UI

Agents is one list of what needs you, what runs and your chats, with the open chat beside it (on a phone the list first).

  • Needs you: each row says why (answered, asks approval, failed). Allow, Deny or Reply right on the row; Snooze, Dismiss and Archive under its ⋯ menu. Its subagents fold to one line "N running".
  • Review: a branch with commits to merge: View diff, Merge or Reject.
  • Working, Done today and Earlier (your other chats; archived ones behind the Archived filter).

In a chat

  • The agent keeps running between turns, also through a companion restart. Write while it works: it reads your message after its step.
  • The chip under the box picks the model and its effort; the default for new chats is under Settings.
  • Paperclip, paste or drop to attach files (5 of 10 MB); the microphone turns speech into text (https only).
  • "Own branch" on a new chat: the agent works in a git worktree of its own (branch chat/<id>); you merge it.
  • Running subagents and background shells show above the box (on a phone folded to "N running ▸"); finished subagents fold away under the chat in the list.
  • Archive takes a chat off the list (Open again brings it back, and so does a new message); × only closes the pane. On a desktop the Agents view tiles your open chats in a grid; the List button in the header shows Review, workers, tasks and earlier chats, with a count of what needs you there.

Which project does my session get?

At every start the server picks the project whose memory and context the session gets:

  1. A token for one project (a guest): always that project, whatever the folder is called, also on Windows.
  2. A linked folder: the project named in .knowledge-project in the folder or a folder above it (skill knowledge-init writes it; a person with several projects is told at session start when a folder is not linked).
  3. Otherwise the folder you start the agent in:
Folder (example)Project
~/<project name>/…, e.g. ~/gardenthat project
anything else, e.g. ~/Workthe default project (homelab)

A folder name counts only when it is exactly the project's name: ~/garden works, ~/GardenPlanner does not.

When it does not work

What you seeCause and fix
401 or "token invalid"Token copied wrongly or revoked. Set it again; ask for a new one if needed.
No context at start (Windows)Git for Windows or Python missing, or the token not in the Credential Manager (cmdkey /list:knowledge shows it). Install both or store the token, then start again.
Setup says "No token"It ran without a terminal (it can only ask in one): run it in a terminal, or set KNOWLEDGE_TOKEN.
A new token, or the old one revokedRun the setup again and answer y when it asks whether to replace the stored token.
The session gets the wrong projectThe folder is not linked: ask your agent to link it (skill knowledge-init), or see "Which project does my session get?".
Docs do not reach the serverNo .knowledge-project in the project root, or its name does not match your token's project.
"used by another process" or "Access is denied" (Windows)An agent or a terminal still has the plugin folder open. Quit Codex and agy, cd $HOME, and run the setup again.
agy: no context, never asks to registeragy plugin list shows no knowledge plugin: an install was cut off. Quit agy and run knowledge-agent.py install agy again.
Codex ignores the context hookMore than one SessionStart hook, or the hook is not trusted yet: open /hooks in Codex.
"writes are allowed only for …"That path is never written through the tools (for example outside a project's docs or memory). Write the note in the project's memory folder.
"this device token is read-only" or "you may only read this project"Your token may read but not write there. Ask the admin for a write token for that project.
"knowledge server unreachable: offline mode"The server is down. The agent works in your offline copy (~/.knowledge/mirror/); what it writes goes up at the next start. A memo changed on both sides (or deleted on the server meanwhile) is kept as <name>.offline-<time>.md to merge.
"knowledge server unreachable and no offline copy on this device"The server is down and this device was never online with it, so there is no copy yet. Check the server address and your network; the copy is made at the first start that reaches the server.
"… is not on PATH: install it first"The setup cannot find that agent or tool. Install it, open a new terminal and run the setup again.
"5 messages wait already" (Chats)The line is full. Wait for the agent, press Force to go first, or Stop.
